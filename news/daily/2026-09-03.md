### 1) Maybe We Shouldn't Be Reviewing All This Code
- Track: better_decisions
- Why it matters to me: AI-generated code changes the economics of code review. If you're building or shipping software (for yourself or your business), understanding when review adds value vs. when it's overhead is a real decision hygiene question. This touches AQ4 directly — what frameworks help you decide when to apply human judgment vs. trusting automation.
- Tradeoff / tension: Skipping review saves time and unblocks velocity, but risks silent failures in critical paths. Over-reviewing slows iteration and creates a false sense of quality. The tension isn't "review vs. no review" — it's *which code deserves which level of human attention*.
- Implication: The default posture of "all code must be reviewed" is breaking under AI-generated volume. A tiered approach — critical paths get scrutiny, disposable scaffolding doesn't — may be the more rational default. This applies beyond code: review everything you can't afford to be wrong about, skim the rest.
