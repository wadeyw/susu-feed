### 3) Quoting Boris Cherny: AI-written production code should have a *higher* bar than human code
- Track: own_business
- Why it matters to me: An explicit governance principle from the person who runs Claude Code: agent-authored code carries no intrinsic sense of codebase health, so the bar must be imposed externally — dense lint rules, many tests, agent-driven E2E tests, daily fuzzers, automated code and security review. "Without these, you can end up with a mess that is hard to maintain." This converts "AI code is lower quality" from a complaint into an engineering plan: the automated guardrail investment is a precondition, not a cleanup project.
- Tradeoff / tension: Guardrails are a fixed up-front cost (CI spend, tooling, maintenance of the rules themselves). Skipping them feels faster now and defers the mess — but the mess compounds silently because agent output keeps arriving at scale. The cost of the bar scales with the rate of agent-authored code: the faster the agents, the heavier the guardrails must be.
- Implication: If I scale agent-assisted coding in any product I build, plan the quality-investment ratio *before* ramping volume. The team question is not "how much do we review?" but "what automated bar are we imposing on agent code, and does it hold up as agent volume doubles?"
