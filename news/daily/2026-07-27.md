## Idea sparks

- The relay market investigation suggests a broader pattern: legitimate infrastructure tools often get repurposed for adversarial ends as soon as they become valuable. This applies beyond AI — CDNs, serverless platforms, and cloud APIs all face similar abuse vectors. A mental framework for "dual-use infrastructure risk" could inform how we design and monitor systems.

- Proof automation via LLMs introduces a question about verification strategy: if LLMs can generate proofs, who verifies the verifiers? The risk shifts from manual proof errors to LLM hallucinations in proof generation. This changes the threat model for formally verified systems — we're trading one class of bugs for another.

- For daughters' education, the Forth article's emphasis on "anything that calculates numbers" as the definition of computer connects to a larger point: redefining tools before teaching their use prevents premature cognitive closure. This principle extends beyond programming to any domain where AI offers automated solutions.
