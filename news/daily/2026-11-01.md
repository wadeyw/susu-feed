### 3) Willison: how ChatGPT accounts get taken over — an exploit in the artifacts/HTML-preview sandbox (Parameter Labs writeup)
- Track: ai_change
- Marker: 📌 watch
- Why it matters to me: Parameter Labs found a multi-step exploit chain against the sandboxed-iframe pattern that ChatGPT uses for interactive HTML artifacts ("HTML previews"), letting untrusted code inside the artifact reach into OpenAI APIs and private data — and the public result was **account takeover**. The reusable lesson: every time we embed generated interactive surfaces (creator-facing dashboards, AI-generated HTML reports, embedded brief builders), the *sandbox boundary is the product requirement*, not an implementation detail. Willison's framing matters because it shows where the attack lives: the gap between "untrusted content" and "trusted API context" inside the same page.
- Tradeoff / tension: tightening sandboxes costs user experience (the whole point of artifacts is live, stateful UI); the vendor's incentive is the looser end. For us, the tension is timing: building our own embedded surfaces now (cheap, we can sandbox properly) vs. waiting and shipping on someone else's half-open sandbox (fast, inherits their exploit surface).
- Implication: one line in the platform requirements doc: "any surface that renders LLM-generated interactive code in the same origin as API context must isolate the two — separate origin or iframe, no shared tokens." Cheap insurance while we don't have those surfaces yet; expensive lesson after.
- Action: watch — file the one-line requirement; revisit when any of our UI embeds generated HTML.
